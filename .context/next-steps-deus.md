## Следующий кирпич: рантайм (P1 из аудита)

План ещё не написан — начать с `.context/plan-10-runtime-*.md` и двух ревью, как обычно.

### 1. Синхронные проверки блокируют пул — самое частое

`gate.ts:24` использует `spawnSync`; `pool` в `team.ts` держит все задачи в одном event loop.
Пока один агент гоняет `npm test`, у остальных не опрашиваются ни permission-запросы, ни
завершение сессии; после разблокировки `Date.now() - started > timeoutMs` (`executor.ts:235`)
даёт **ложный** `step timed out` и обрывает исправную сессию. Это дефолтный `--team-parallel 3`.

**Сделать:** `runCheck`/`runGate` → async (`spawn` + await), протянуть async через
`pipeline.ts`, `apply.ts`, `team.ts` (baseline, pre-gate, post-gate, resolve-чеки).
**Проверка:** медленный чек (10 с) + две параллельные задачи: ни одна не получает таймаут;
тест на `runGate` с двумя одновременно запущенными проверками.

### 2. Нет таймаутов HTTP — процесс висит с занятым lock

`executor.ts`, `sessions.ts`, `wake.ts` дергают клиент без `RequestOptions.signal`. Полуотворённое
соединение блокирует `session.get` навсегда; сигнал Ctrl-C до клиента не доходит, второй SIGINT —
единственный выход.

**Сделать:** прокинуть `AbortSignal` (общий `controller.signal` + per-call timeout) в
`session.create/prompt/get`, `permission.list/reply`, `message.list`, follow-up.
**Проверка:** тест с фейковым клиентом, который не отвечает: шаг завершается по таймауту, процесс
не висит, lock снимается.

### 3. Потолок стоимости инертен для модели без цены

`pricing.ts` возвращает 0 для неизвестной модели; дефолтной `opencode-go/hy4-flash-free` в таблице
нет. `--max-cost` не срабатывает, а итог печатает `cost=~$0.0000`.

**Сделать:** «неизвестная цена» ≠ 0 (`estimateCost` → `undefined`, `costEstimated = true`);
бесплатные модели определять явно (по `free` в id или записью в таблице); если `--max-cost`
задан, а цена шага неизвестна — останавливать прогон с внятной ошибкой; печатать `cost=unknown`,
а не нули.
**Проверка:** тест «неизвестная модель + `--max-cost` → отказ»; тест «цена из провайдера
перекрывает таблицу».

### 4. Мелочи, которые стоит взять в тот же кирпич

- стоимость проверяется между задачами, но не после каждого воркера — добавить проверку после
  пула (внутри `pool` не нужно, достаточно после каждого завершения).
- `--max-cost` из `deus.json` читается из репозитория (агент может поднять потолок) — при
  доверенных агентах это допустимо, но стоит одной строкой отметить в README.

## Осознанно не чиним (при выбранной модели угроз)

Записано в README «Границы доверия»; не считать багами без смены модели:

- доска подделываема (`submit --board-gate passed`, актор — строка);
- гейт исполняет код агента (`npm test` из его worktree, `deus.json` из влитой ветки);
- `.deus`/`.git/hooks` доступны агенту, shell не изолирован;
- фильтр секретов — эвристика по именам;
- `node_modules` линкуется симлинками в проект (проверки должны быть read-only);
- сетевые ФС и несколько хостов не поддерживаются.
